Plugin protocol v1

Build anything for the notch

A Nook plugin is a folder with a small manifest and a program, written in any language. Your program prints JSON describing its tile, Nook draws it in the notch's glass style and sends back clicks, typing, hotkeys and dropped files. You don't need Rust and you don't rebuild Nook.

Any language

Python, Node, PowerShell, Go, C#, Rust, a .bat file. If it can read and write lines, it can be a plugin.

Looks native

Describe what to show (text, rings, lists, buttons, a canvas), and Nook draws it with its own springs, theme and accent color.

Safe to crash

Each plugin runs in its own process. If it crashes, it restarts and the notch keeps running.

Quick start

  1. Make a folder in %APPDATA%\Nook\plugins\, for example hello.
  2. Add plugin.toml: 
    id   = "hello"
name = "Hello"
icon = "hand-waving"        # any icon from phosphoricons.com
size = "wide"               # small | wide | large
run  = ["python", "main.py"]
  3. Add main.py. It prints one JSON object per line and reads one per line: 
    import json, sys

def send(msg):
    print(json.dumps(msg), flush=True)

clicks = 0
def draw():
    send({"type": "tile", "view": {
        "type": "row", "align": "center", "children": [
            {"type": "text", "text": f"Hello x{clicks}", "size": "title"},
            {"type": "spacer"},
            {"type": "button", "id": "wave", "icon": "hand-waving"},
        ]}})

draw()
for line in sys.stdin:                 # Nook's messages, one per line
    msg = json.loads(line)
    if msg["type"] == "event" and msg["id"] == "wave":
        clicks += 1
        draw()
  4. Turn on Plugin dev mode in Nook's Settings. Nook loads a new plugin folder within a few seconds without a restart, and with dev mode on it also restarts your plugin every time you save. The tile is added after the built-in ones. Use the pencil in the grid to move or resize it.

That's the whole protocol. The rest of this page lists everything else you can use. For ready-made examples, see examples/plugins/ in the repository: a counter, a to-do list, a PowerShell disk monitor and an analog clock drawn on a canvas.

How it works

  • Nook looks for plugin folders when it starts, starts each plugin's program in that plugin's own folder, and sends it a hello message.
  • Your program sends views: trees of components such as row, text, button and ring. Send a new tree whenever something changes, and the latest one replaces the previous one.
  • When the user interacts with a control, Nook sends an event with that control's id.
  • A plugin has a tile in the grid and, if it wants one, a full page that opens when the tile is clicked.
  • Your program can also put a badge in the collapsed pill, light its tile, open the notch, copy text or open a URL.

Live and poll modes

live default

Nook starts your program once and keeps it running. Your program reads messages from stdin and writes to stdout whenever it wants. Use it for timers, sockets, animation, or anything that keeps state. If the program exits, Nook restarts it up to three times a minute.

poll

Nook runs your program, reads everything it printed, and waits. It runs it again after interval seconds, or right away when the user clicks something (the event is in NOOK_EVENT). Use it for small scripts that report something. Each run gets 30 seconds.

# plugin.toml: mode = "poll", interval = 30,
#   run = ["powershell", "-NoProfile", "-ExecutionPolicy", "Bypass", "-File", "battery.ps1"]
$b = Get-CimInstance Win32_Battery
@{ type = 'ring'; value = $b.EstimatedChargeRemaining / 100
   label = "$($b.EstimatedChargeRemaining)%"; tooltip = 'Battery' } |
  ConvertTo-Json -Compress

If you print a single component (anything without a tile/page/… type), Nook uses it as the tile, which is handy for small scripts. In poll mode the output can be one JSON document, even pretty-printed, or one message per line.

Views

A view is a tree of components. Every component has a type and can have a tooltip. Layout is simple:

  • column stacks its children downward and row places them left to right. gap sets the space between them (default 6).
  • A spacer with no size pushes everything after it to the far end. For example, [title, spacer, button] puts the button on the right.
  • align (start, center, end) aligns children on the other axis. On a column, justify places the whole column at the top, middle or bottom of the available space.
  • Add "scroll": true to a column on a page when it may be taller than the space.
{ "type": "tile", "view":
  { "type": "row", "align": "center", "gap": 10, "children": [
    { "type": "icon", "icon": "cloud-sun", "size": 28, "color": "accent" },
    { "type": "column", "gap": 0, "children": [
      { "type": "text", "text": "Tbilisi", "size": "small", "color": "dim" },
      { "type": "text", "text": "21°  Sunny", "size": "title" } ] } ] } }

Colors

Theme names follow the user's light or dark theme and accent color: text, dim, faint, accent, on_accent. Fixed colors: red orange yellow green teal blue purple pink white black transparent. You can also use #RGB, #RRGGBB or #RRGGBBAA. Prefer the theme names so your plugin looks right in both themes.

Icons

Use any of the 1,500 Phosphor names, such as "cloud-sun", "cloud_sun" or "CloudSun". "fill": true draws the filled style. An unknown name shows a question mark.

Nook draws unknown component types as nothing. A plugin written for a newer Nook still works in an older one.

To animate, send a new tree each frame from a live plugin. About 30 updates a second works well for a tile. When nothing is moving, send nothing: Nook uses no CPU while idle, and your plugin shouldn't either.

SDKs and languages

The repository has two optional, dependency-free helpers in sdk/. Copy the file next to your program.

import nook

app = nook.Plugin()
tasks = app.load("tasks", [])              # JSON in NOOK_DATA_DIR

def draw():
    app.tile(nook.row([nook.ring(0.3, label=str(len(tasks))), nook.text("Tasks")], align="center"))
    app.page(nook.column([
        nook.text_input("new", hint="Add a task"),
        nook.list_view([nook.item(str(i), t) for i, t in enumerate(tasks)]),
    ], scroll=True))

@app.on("new")
def add(e):
    if e["kind"] == "submit":
        tasks.append(e["value"]); app.save("tasks", tasks); draw()

@app.every(60)
def tick(): draw()

draw()
app.run()
const nook = require("./nook");
const app = new nook.Plugin();
let on = false;
const draw = () => app.setTile(nook.row([
  nook.icon("lightbulb", { fill: on, color: on ? "yellow" : "dim" }),
  nook.spacer(),
  nook.toggle("light", on),
], { align: "center" }));
app.on("light", (e) => { on = e.value; draw(); /* call your smart-home API here */ });
draw();

Any other language

There's nothing else to it. Read lines from stdin, write lines to stdout, and flush after each line. Some reminders:

  • Flush after every line. Python and Node get PYTHONUNBUFFERED set and line-flush on their own. In C, Go, Rust or C#, flush stdout yourself.
  • Write UTF-8, one JSON object per line, with no newlines inside the object.
  • stderr goes to Nook's log, and the last lines appear on the tile if your plugin stops. Use stderr for debug prints.
  • A compiled plugin can include its binary: run = ["bin/my-plugin.exe"].
out := bufio.NewWriter(os.Stdout)
send := func(v any) { b, _ := json.Marshal(v); out.Write(append(b, '\n')); out.Flush() }
send(map[string]any{"type": "tile", "view": map[string]any{"type": "text", "text": "Hi from Go"}})
sc := bufio.NewScanner(os.Stdin)
for sc.Scan() { /* json.Unmarshal(sc.Bytes(), &msg) … */ }

Develop and debug

  1. Keep your plugin where you work on it. Point Nook at the folder that contains it, then run Nook from a terminal: 
    $env:NOOK_PLUGIN_PATH = "C:\code\my-plugins"     # ; separates folders
$env:NOOK_PLUGIN_DEV  = "1"                       # dev mode, without touching Settings
cargo run --release -- --pinned --page=plugin:hello
    In dev mode (Settings, or NOOK_PLUGIN_DEV=1 / --plugin-dev for one run), saving any file in your plugin's folder restarts it and re-reads plugin.toml. Plugin folders that appear or go are loaded or unloaded live either way. --page=plugin:<id> opens on your page.
  2. Test without Nook. Your plugin is just a program, so send it messages yourself: 
    '{"type":"event","id":"wave","kind":"click"}' | python main.py
  3. Read the log. %APPDATA%\Nook\nook.log has every plugin's stderr, log messages and any line Nook couldn't parse, with the reason (for example bad "button" view: missing field `id`).
  4. When it crashes, Nook restarts the plugin up to three times a minute. After that the tile shows Stopped · click to restart, and hovering over it shows the error and the last lines of stderr.

Plugins are searched for in this order: %APPDATA%\Nook\plugins, plugins\ next to nook.exe, then each folder in NOOK_PLUGIN_PATH. If two plugins have the same id, the first one found is used.

Share a plugin

  • A plugin is a folder, so share it as a zip or a Git repository. Users unzip it into %APPDATA%\Nook\plugins\.
  • Add a README that says which runtime your plugin needs (Python 3.8+, Node 18+, …). For zero setup, use PowerShell or ship a compiled binary.
  • Tag your repository nook-plugin on GitHub so others can find it.
  • Keep your plugin's data in NOOK_DATA_DIR, so updating the plugin folder never deletes it.
Plugins are programs. A plugin runs with the same rights as Nook, just like any app you install. Only install plugins whose code you've read or whose author you trust. Nook makes no network calls itself. If a plugin needs the internet, the plugin makes those calls, and its README should say what it sends and where.

Ideas

Some ideas to get started:

  • Weather and rain radar for your city
  • CI status: a red ring when the build breaks
  • Stock or crypto ticker with a sparkline
  • Pomodoro that dims the pill between sessions
  • GitHub notifications, with a badge pulse when one arrives
  • Spotify / Home Assistant / Hue controls
  • Ping and latency to your servers
  • Next meeting countdown from an .ics feed
  • Translate the clipboard (send it to your favorite API)
  • Habit tracker with a week of dots on a canvas
  • Docker containers: start, stop, logs
  • A tiny game: Snake or 2048 on a large tile
  • Local LLM prompt box (Ollama, LM Studio)
  • Drop images to compress or convert them
  • Word of the day, quote, NASA picture of the day
  • Battery health and charge history
  • Steam friends online
  • World clocks for your team (see the analog clock example)

Built-in modules (Rust)

Plugins cover most ideas. Write a built-in module instead when you need to draw with egui directly, hook into Windows APIs inside the process, or run every frame. Built-ins implement the Module trait in crates/ui/src/module.rs:

use nook_ui::module::{Module, TileCtx, TileSize};
use nook_ui::icons;

#[derive(Default)]
pub struct MyTile { clicks: u32 }

impl Module for MyTile {
    fn id(&self) -> &'static str { "my_tile" }
    fn name(&self) -> &str { "My tile" }
    fn icon(&self) -> &'static str { icons::SPARKLE }
    fn size_hint(&self) -> TileSize { TileSize::Small }
    fn ui_tile(&mut self, ui: &mut egui::Ui, _ctx: &mut TileCtx<'_>) {
        if ui.button(format!("{}", self.clicks)).clicked() { self.clicks += 1; }
    }
}

Register it in crates/modules/src/lib.rs (register_all) and open a pull request. Follow the rules the rest of the codebase follows: nothing in ui_tile may block (do work on a thread and drain a channel in on_tick), return None from next_repaint when idle, no unwrap() outside tests, and keep cargo clippy --workspace --all-targets -- -D warnings clean. The plugin host itself is in crates/modules/src/plugins/, if you want to add a component type or message.
